# AI PM 經理人班 — AI 工具與 Agent 教學規範

**適用範圍**：W04–W07（AI 工具應用）主要適用；W03、W08、W09、W10 部分掛載
**版本**：v1.0（2026-09-18）
**性質**：開發守則 + 教師端參考。**這份文件本身不是學員教材**，是寫 W04–W07 教材時的內容基準與事實來源。
**依據**：OpenAI（ChatGPT）與 Anthropic（Claude）官方使用手冊與技術文件，來源清單見附錄 C，查證日期 2026-09-18。

## 零、這份文件要解決的問題

`課程邊界與驗證規範.md` 的**邊界 B 硬性規則 1** 要求「廠牌中立，不綁定特定工具」。但教「使用 AI 工具」如果完全不碰真實產品，會變成兩種失敗：

- **懸空**：學員讀完「提示要有角色、任務、脈絡」，打開 ChatGPT 還是不知道第一句要打什麼。
- **失效**：教材寫滿按鈕位置與功能清單，半年後全錯。

解法是**把內容切成兩層**，而不是在「教」與「不教」之間二選一：

| 層 | 內容 | 是否進學員教材 | 過期風險 | 對應邊界規則 |
|---|---|---|---|---|
| **原則層** | 概念、判斷準則、提示寫法、派工框架、決策樹 | ✅ 進主教材，廠牌中立表述 | 低（3 年以上） | 邊界 B 界內 |
| **廠牌層** | 兩家的功能名稱、方案差異、用量上限、可否建立 | ⚠️ 只進**可單獨更新的附錄** | 高（3–6 個月） | 邊界 B 硬性規則 2 |

**原則層的內容必須「兩家官方文件都說得通」才寫進教材。** 只有一家提出的主張，若不是通用原則，一律降級到附錄或刪除。這是本文件最重要的一條規則——它同時滿足了「有官方依據」與「廠牌中立」。

## 一、原則層：提示（Prompt）教學規範

### 1.1 兩家官方文件的交集

兩家的提示指引各有詞彙，但去掉詞彙差異後高度重疊。下表是**交集**，也是 W04 教材的骨架：

| 交集原則 | OpenAI 的說法 | Anthropic 的說法 | 教材要教的動作 |
|---|---|---|---|
| **講清楚，不要靠猜** | 給「精確、明確的指令」與具體邏輯 | 黃金法則：把提示給一位沒有背景的同事看，他看不懂，模型也看不懂 | 寫完提示，先找人讀一遍 |
| **給格式與結構** | 用 Markdown／XML 分出身分、指令、範例、脈絡四區 | 用 XML 標籤把指令、脈絡、範例、輸入分開 | 提示分段落，不要一整段 |
| **給範例** | 少樣本（few-shot）：放輸入／輸出範例，範例要多樣 | 3–5 個範例效果最好，要相關、要涵蓋邊界案例 | 範本庫每個範本附 1 個範例 |
| **給角色** | 用最高優先的指令訊息設定行為 | 一句話的角色設定就有差別 | 範本第一行固定寫角色 |
| **長資料放前面** | 常重複使用的內容放開頭 | 20k tokens 以上的長資料放在問題**之前**，可改善約 30% | 貼長文件時，先貼文件再問問題 |
| **要它動，就說動** | — | 「請建議修改」只會得到建議；「請修改」才會動手 | 動詞決定產出，教學員檢查動詞 |
| **正面指令優於禁令** | 用正面、具體的指令，而非一長串禁止事項 | 不要寫「不要用清單」，要寫「用流暢的段落書寫」 | 把「不要 X」改寫成「請 Y」 |
| **要它先想再答** | 推理型模型給高階目標、少給步驟；一般模型給明確步驟 | 引導思考、思考鏈；但只在需要多步推理時用 | 複雜題加一句「先列出思路再作答」 |
| **拆步驟優於一次到底** | — | 提示鏈（prompt chaining）：拆成有先後的多次呼叫 | 大任務拆成 3–4 次對話 |

### 1.2 五要素框架的官方對應（W04 核心）

原大綱的「五要素：角色、任務、脈絡、格式、限制」保留，並補上官方對應以強化可信度：

| 要素 | 一句話 | 官方依據 |
|---|---|---|
| 角色 | 你要它以什麼身分回答 | 兩家都建議明確設定角色／身分 |
| 任務 | 你要它產出什麼，用什麼動詞 | 明確、具體的指令；動詞決定它做不做 |
| 脈絡 | 它需要知道什麼才能做對 | 把專有資料放進提示（檢索增強的概念原型） |
| 格式 | 產出長什麼樣 | 明確指定輸出格式與結構 |
| 限制 | 什麼不要做、什麼不能假設 | 用正面表述的限制，處理邊界案例 |

### 1.3 教材撰寫規則

1. 示範一律用**自然語言提示**，不得出現需要學員讀懂的程式碼或 API 參數（邊界 A）。
2. XML 標籤的教法：只教「用 `<脈絡>`、`<任務>` 這種標記把提示分區」的**概念與好處**，不教標籤語法規則。學員層級寫成「用三個小標題把提示分段」即可達成相同效果。
3. 提到「約可改善 30%」這類數字時，必須標註「依 Anthropic 官方文件，查證日期 2026-09-18」，並列在易過期區塊。
4. **提示工程的極限**（原大綱 W04 核心概念 4）必須保留並強化：官方文件明確指出，提示改不動的問題屬於「工具能力」或「資料」層面的限制——這是往 W03 可行性判斷的回扣點。

## 二、原則層：AI 工具的四個使用層級

教學上把「用 AI」拆成四層，**層級越高，投入越高、回收也越高**。這是 W04–W07 的縱軸，也是第六節決策樹的基礎。

| 層級 | 名稱 | 學員在做什麼 | 兩家對應的功能類別 | 掛在哪一週 |
|---|---|---|---|---|
| **L1** | 單次對話 | 問一件事、改一段文字 | 一般對話、搜尋、檔案上傳、資料分析 | W04 |
| **L2** | 有脈絡的工作區 | 把一個專案的檔案與規則放在一起，之後每次對話都帶著 | 工作區／專案（Projects）＋專屬指令 | W05、W06 |
| **L3** | 可重複使用的資產 | 把「我每次都這樣做」變成別人也能用的東西 | 提示範本、自訂助理、技能（Skills） | W04 產出、W10 團隊規範 |
| **L4** | 交辦型 Agent | 交出一個目標，讓它自己跑多步驟並回報 | Agent 模式、深度研究、排程任務 | W07、W09 |

**教學紅線**：L1→L3 是「個人生產力」，學員自己就能決定；**L4 開始牽涉資料權限與對外行為，必須先問公司規定**（邊界 B 硬性規則 3）。教材在進入 L4 之前一定要先放這句話。

## 三、原則層：Agent 教學規範

### 3.1 什麼是 Agent（兩家官方定義的交集）

- OpenAI：Agent 是「能代替你獨立完成任務的系統」——由模型決定流程、能使用工具、在明確的**護欄（guardrails）**內運作。
- Anthropic：區分**工作流（workflow）**與**Agent**。工作流是預先寫好的步驟；Agent 是「由模型自己決定要怎麼做、用什麼工具」。

**寫進教材的白話定義（廠牌中立）**：

> **Agent（代理）**：你給它一個目標，它自己拆步驟、自己決定用什麼工具、做完回報給你。對比一般對話：對話是你問一句它答一句，Agent 是你交辦一件事它做完再回來。

**必須同時教的對比概念**：

> **工作流（Workflow）**：步驟由人事先定好，AI 只負責每一步裡的判斷。比 Agent 可預測、可重現、便宜。

**教學重點（兩家都強調，務必寫進教材）**：**先用工作流，不夠再用 Agent。** Anthropic 明確指出 Agent 會拉高延遲與成本，換來的是彈性；OpenAI 建議先確認流程確實需要 Agent 再投入。對經理人而言，這是一句可以直接在會議上用的判斷。

### 3.2 什麼情況才該用 Agent（三個判準）

整合兩家判準，收斂成經理人版的三問：

| 判準 | 問法 | 官方依據 |
|---|---|---|
| **1 · 步驟事先講不清楚** | 這件事的步驟，我能不能事先寫成一張 SOP？能 → 用工作流，不用 Agent | Anthropic：Agent 適用於「無法預先預測步驟」的開放性問題 |
| **2 · 需要判斷，不只是規則** | 這裡有沒有例外、灰區、要看情況的判斷？沒有 → 用現成軟體或規則就好 | OpenAI：適用於「複雜決策、規則難以維護、大量非結構化資料」三種場景 |
| **3 · 值得付彈性的代價** | 慢一點、貴一點、偶爾要重跑，我能接受嗎？ | Anthropic：Agent 以延遲與成本換取效能 |

**三問有任一個答「否」，就不是 Agent 的場景。** 這一條要明確寫在教材裡——本課程最常見的學員誤區就是「什麼都想派給 Agent」。

### 3.3 ★ PM 如何指派任務給 Agent：六欄任務書

這是 W07 的核心產出，也是本規範最重要的原創整合。它把 OpenAI 的「模型／工具／指令 + 護欄 + 人工介入」與 Anthropic 的「明確、可逆性、停止條件」翻譯成 PM 已經熟悉的**派工語言**——因為指派任務給 Agent 和指派任務給一位新進同事，需要交代的東西幾乎一樣。

| # | 欄位 | 你要交代什麼 | 沒交代會發生什麼 | 官方依據 |
|---|---|---|---|---|
| 1 | **目標** | 做完之後，世界長什麼樣。用名詞寫出交付物，不要寫「幫我看一下」 | 它做了一堆事，但不是你要的那件 | 明確、具體的指令；動詞決定它動不動 |
| 2 | **範圍與邊界** | 哪些不要做、哪些不要碰、做到哪裡停 | 過度發揮：多做了你沒要的、改了你沒要它改的 | 避免過度工程；正面表述的限制 |
| 3 | **脈絡與資料** | 它需要知道什麼、資料在哪、哪些是權威來源 | 它自己上網找，或直接編（幻覺） | 把專有資料放進脈絡；先查證再回答 |
| 4 | **工具與權限** | 可以用哪些工具、能碰哪些系統、不能碰什麼 | 權限過大 → 動到不該動的；權限不足 → 卡住空轉 | 工具是 Agent 的三大組件之一；只開必要的整合 |
| 5 | **驗收標準** | 怎麼算做完、你會怎麼檢查、要附什麼證據 | 你拿到一份看起來很完整、但無法驗證的東西 | 驗收條件；要求附引用與來源 |
| 6 | **停止與回報規則** | 什麼情況必須停下來問人、什麼情況直接回報失敗、最多試幾次 | 它硬做到底，或在同一個坑裡反覆重試 | 停止條件、最大回合數、失敗時交還控制權 |

**教材呈現方式**：一張 A4 的「Agent 任務書」空白表單 + 一份填好的範例（建議用「整理上季客訴、分類成前五大問題、附原始案件編號」這種企業內部流程場景，符合邊界規範第三節「至少一個企業內部案例」）。

**作業設計**：學員用六欄任務書寫一份給 Agent 的任務書，**並且找同事照著這份任務書做一次**。同事做出來的東西不對，就是任務書寫得不夠清楚——這正是官方的黃金法則（同事看不懂，模型也看不懂），而且不需要學員真的有付費帳號才能完成作業，同時解決了「非 PM 背景替代版」的需求。

### 3.4 護欄與人在迴路：可逆性分級

兩家都以「行動是否可逆」作為要不要讓 AI 自己做的核心判準。這一節與 W09（AI 倫理、風險與治理）共用，是 W07 與 W09 的接點。

| 級別 | 行動性質 | 例子 | 處理方式 |
|---|---|---|---|
| **A · 可逆、影響只在自己** | 讀取、草稿、整理、試算 | 讀檔、寫草稿、跑分析 | 讓它自己做，事後檢查 |
| **B · 可逆但別人看得到** | 對外發出但可撤回或更正 | 寄內部信、發訊息、建立票單 | 先看過再送出（人工核准） |
| **C · 難以復原** | 覆寫、刪除、強制更新 | 刪檔、覆蓋正式文件、改資料庫 | 一律人工確認，不得預設自動 |
| **D · 對外承諾或動錢** | 付款、簽署、對客戶承諾 | 下單、退款、回覆客戶申訴 | 不交給 Agent，僅由它準備草稿 |

**必須同時教的三個具體風險（有官方依據，不是想像的）**：

1. **提示注入（prompt injection）**：Agent 讀到的網頁或文件裡，可能藏著給 AI 的指令。兩家都把這列為 Agent 的主要威脅並有偵測機制。**教材白話版**：它讀到的東西可能在對它下命令，而不只是被它讀。
2. **不要把密碼交給 Agent**：官方建議在需要輸入敏感資訊時由人接手操作（ChatGPT agent 的「接管模式」在該狀態下不擷取畫面截圖）。**教材白話版**：需要登入的步驟，人自己來。
3. **只開必要的權限，用完檢查**：官方建議每個任務只啟用必要的應用連結，並定期檢視授權。**教材白話版**：權限按任務開，不要一次全開。

### 3.5 Agent 章節的教學禁區

- ❌ 不教 Agent 框架、SDK、多 Agent 架構實作（邊界 B 界外）。
- ❌ 不教「哪一家的 Agent 比較強」——能力差異變動太快，且非本課程判斷重點。
- ❌ 不在教材寫死用量上限、方案價格、可用地區（進附錄 A）。
- ⚠️ 多 Agent 協作（一個主管型 Agent 指揮多個專才 Agent）**只講到「這個詞在會議上代表什麼」的層級**——讓學員聽得懂技術團隊在說什麼，不教設計方法。

## 四、★ 工具選擇決策樹

W04 開場與 W07 收尾各用一次。目的是讓學員停止問「我該用哪個 AI 工具」，改問「我這件事屬於哪一層」。**決策樹只描述能力類別，不出現產品名稱**（產品對照在附錄 A）。

```
這件事，我要 AI 幫我做什麼？
│
├─ Q1 只是問一件事／改一段文字，問完就結束？
│   └─ ✅ L1 一般對話
│       ‧ 需要最新資訊 → 開啟搜尋功能
│       ‧ 有檔案要看 → 上傳檔案
│       ‧ 有數字要算、要圖表 → 用資料分析功能，不必寫程式
│
├─ Q2 同一個專案我會問很多次，而且每次都要先解釋一堆背景？
│   └─ ✅ L2 工作區／專案
│       ‧ 把規格、會議紀錄、既有文件放進工作區
│       ‧ 把「你回答時要遵守的規則」寫成工作區專屬指令
│       ⚠️ 上傳前先確認：這些檔案依公司規定可以放進外部工具嗎？
│
├─ Q3 我每次都用同一套做法，而且想讓團隊其他人也照著做？
│   └─ ✅ L3 可重複使用的資產
│       ‧ 只是固定問法 → 提示範本（門檻最低，先做這個）
│       ‧ 固定問法 + 固定參考資料 → 自訂助理
│       ‧ 固定流程 + 固定產出格式，要跨人跨時間一致 → 技能（Skill）
│       💡 官方共同建議：規則、語氣、流程寫進「指令」；參考資料放進「知識檔案」，不要混在一起
│
├─ Q4 這件事有很多步驟，需要它自己上網查、自己開檔案、自己決定下一步？
│   └─ 先過 3.2 的三問（步驟講不清楚？需要判斷？值得付代價？）
│       ├─ 有任一個「否」 → ❌ 退回 Q1–Q3，或用現成軟體／既有流程
│       └─ 三問全是 → ✅ L4 交辦型 Agent
│           ‧ 只是要一份有引用的研究報告 → 用深度研究類功能（比較可控，先試這個）
│           ‧ 要它真的去操作網站、填表單、動檔案 → 用 Agent 模式
│           ‧ 每天／每週固定要跑 → 加排程任務
│           📋 必備：填完 3.3 六欄任務書
│           🚦 必備：用 3.4 可逆性分級決定哪幾步要人工核准
│           ⚠️ 必備：先確認公司對「AI 代為操作系統」的規定
│
└─ Q5 我要它接進公司系統、或做成產品裡的功能，讓客戶／同事天天用？
    └─ 🛑 這已經不是「使用 AI 工具」，是「建 AI 系統」
        → 你的工作是把 3.3 的六欄任務書寫好，交給工程團隊
        → 你需要聽得懂的詞：API、MCP、RAG、脈絡長度（見第五節）
        → 回到 W03 四問檢核表做可行性判斷，再回到 W11 算 ROI
```

**四個「不要用 Agent」的訊號**（教材以警示框呈現）：

1. 這件事錯了會有人受害、會動錢、會對客戶做出承諾。
2. 我自己都說不清楚做完長什麼樣。
3. 步驟其實很固定——那是工作流或既有軟體的工作。
4. 我沒辦法驗證它做得對不對。

## 五、概念認識層：讓經理人聽得懂技術團隊在說什麼

**這一節的教學目標不是會用，是聽得懂 + 知道何時該找誰。** 每個名詞只給三件事：白話定義、對 PM 的決策含義、什麼時候該找工程師。嚴禁出現參數、程式碼、架構圖（邊界 A、B）。

| 名詞 | 白話定義 | 對你的決策含義 | 何時該找工程師 |
|---|---|---|---|
| **API** | 讓別的軟體直接呼叫 AI 的管道，不經過聊天視窗 | 要把 AI 變成產品功能、要大量自動處理，就會走到這裡；此時**每一次呼叫都有成本** | 「我要讓這件事在系統裡自動發生，不要每次有人去貼提示」 |
| **MCP**（Model Context Protocol） | 讓 AI 工具連到外部資料與系統的**通用接頭**。官方的比喻是「AI 的 USB-C」。已由 Anthropic 提出並開源，兩家主要工具都支援 | 你想問的「能不能讓它直接讀我們的系統」，答案通常是「可以，看有沒有現成接頭」。有現成接頭 → 幾天；要自建 → 專案 | 「我們的 ___ 系統有沒有現成的接頭？」 |
| **技能 / Skills** | 一包給 AI 的「作業指引」（做法、格式、參考檔案），需要時才載入 | 這是**把團隊 know-how 變成可交付資產**的方式，比一份沒人看的 SOP 更容易被真的使用 | 「我們的 ___ 流程能不能做成一個技能，全部門共用？」 |
| **RAG**（檢索增強生成） | 回答前先去指定的資料庫裡找資料，再根據找到的內容回答 | 這是對付「幻覺」與「它不知道我們公司的事」最常見的做法，也是 W09 幻覺對策的技術對應 | 「答案要有出處、要可追溯到我們的文件」 |
| **脈絡長度 / Context** | AI 一次能「看在眼裡」的資訊量上限 | 資料太多塞不進去時，就得選擇、摘要或改用檢索。這是很多「它怎麼忘記前面說的」的真正原因 | 「我們的資料量會不會超過它一次看得完的量？」 |
| **護欄 / Guardrails** | 限制 AI 能做什麼、不能做什麼的機制（分類判斷、黑名單、敏感資料過濾、人工核准） | **這是 PM 的設計工作，不是純技術工作。** 護欄要放在哪幾步，由你依 3.4 決定 | 「這幾步我要人工核准，系統做得到嗎？」 |
| **人在迴路**（human-in-the-loop） | 刻意在流程中保留人的審核／介入點 | 官方明確建議在高風險行動與反覆失敗時交還控制權給人 | 「失敗時要交還給誰、怎麼交？」 |
| **提示注入**（prompt injection） | 有人把指令藏在 AI 會讀到的內容裡，讓它照著做 | Agent 能讀外部內容就有這個風險。這是「Agent 能不能連公司系統」必問的安全問題 | 「它如果讀到惡意內容會怎樣？」 |

**表格後必須放的一段話（教材原文建議）**：

> 這八個詞你不需要會做，但你需要在會議上聽得懂。因為當技術團隊說「這要走 API」「這要接 MCP」「這要做 RAG」時，他們講的其實是**時程、成本與可行性**——而那正是你要判斷的事。

### A.2 兩家官方明文的限制與控制（教學時直接引用）

**ChatGPT agent**

- 僅付費方案可用；有每月次數上限（官方文件所列：Plus 40 則／月、Pro 400 則／月）。
- 無法存取已同步的應用資料（例如 Google Drive 同步內容），但可透過對話式整合存取該服務。
- 部分網站因安全或合規原因被封鎖，無法造訪。
- 安全控制：**接管模式**（由使用者手動操作瀏覽器輸入敏感資訊，該狀態下不擷取截圖）、**高影響行動需使用者確認**、**特定網站強制監看模式**、**提示注入偵測**。
- 官方建議：不要直接輸入密碼（改用接管模式）、每個任務只啟用必要的應用、用具體而非模糊的指令、定期檢視應用授權、發現異常立刻停止。

**Custom GPTs**

- ⚠️ **重要變動**：官方文件明文載明「**新建與發布 GPT 不適用於個人 ChatGPT 帳號，包含 Free、Go、Plus、Pro**」；**僅 Business／Enterprise／Edu 工作區**使用者可在工作區設定與權限允許時建立、編輯、發布 GPT。個人方案仍可**使用**既有的 GPT。
  → **對課程的直接影響**：W04／W10 的作業不得預設「學員能自己建一個 GPT」。相同教學目標改以「提示範本庫」達成（門檻最低、廠牌中立、任何方案都做得到），自訂助理與技能僅作為「團隊層級可以怎麼做」的介紹。
- 知識檔案上限 20 個，每個 512 MB。
- 官方建議：知識檔案放「參考資料」，規則、語氣、流程放「指令」，兩者不要混。指令用正面具體的表述（「做 X」），而非一長串禁止事項。

**ChatGPT Projects**

- 檔案上限依方案：Free 5、Plus/Go 25、Pro/Business/Enterprise/Edu 40；單次最多同時上傳 10 個。
- 可連結 Google Drive 資料夾與 Slack 頻道作為專案來源。
- 專案指令覆蓋全域自訂指令，且僅作用於該專案。

**Claude Projects**

- 免費帳號最多 5 個專案。
- Team／Enterprise 可分享專案，權限分「可檢視」與「可編輯」。
- 封存的專案需先解除封存才能刪除。

**Claude Skills**

- 需先啟用程式碼執行功能；Claude 會在判斷相關時自動使用，不需明確呼叫。
- Team／Enterprise 管理者可全組織佈建。
- 官方建議：先用內建技能再自建；描述要清楚具體以便正確觸發；不同用途分開做成不同技能；**只安裝來自可信來源的技能**。

**深度研究（deep research）**

- 適用於需要綜合多個來源的多步驟問題；快速查詢用一般搜尋即可。
- 官方明確要求：**使用或分享前先檢查引用，確認來源真的支持該主張。**

### A.3 每次重新查證要確認的項目
