# 驗證審查報告 v1 — 12 週課程大綱 + W01 教材

**審查依據**：`00-課程大綱/課程邊界與驗證規範.md` v1.0
**審查對象**：`12週課程大綱.md` v1.0、`W01-互動教材.html`、`W01-自學指南.md` v1.0
**審查方式**：以五類驗證者視角逐項檢核（模擬審查，待真人驗證者複核）
**審查日期**：2026-09-18

---

## 一、總評

| 項目 | 結論 |
|---|---|
| 三條邊界的整體遵守度 | **良好**。無程式碼、廠牌中立、不碰數學，W01 執行得相當乾淨 |
| 最大風險 | **非 PM 背景學員的術語門檻**，以及 **W06／W12 的時數與難度爆量** |
| P0 問題 | 4 項 |
| P1 問題 | 7 項 |
| P2 建議 | 5 項 |
| 建議 | 大綱不必重寫，但 W02–W12 開發前須先處理 P0，否則問題會被複製 12 次 |

**一句話**：課程的骨架與語氣是對的，問題全部集中在「邊界的下緣」——不是講太深，是**沒有為最弱的那一類學員鋪好入口**。

## 二、逐角色審查發現

### 驗證者 1 · 現職產品經理

**評分**：專業正確性 4.5 / 實務相符度 4.5 / 可跳過路徑 **2.0**

**做得好**

- 「傳統軟體輸出確定、AI 輸出機率性」這條主線抓得準，是實務上最常被誤解的地方。
- 五個具體差異表中，「資料是產品的原料而非產物」這一條很有價值，多數入門教材會漏。
- 「原型的目的是淘汰想法，不是做出產品」（W06）——這句話值得保留為全課金句。

**問題**

- **[P1-1] 缺少已有 PM 經驗者的加速路徑。** W01 的五個差異、W05 的使用者研究、W06 的 PRD 骨架，對現職 PM 幾乎是複習。整整三週他們會覺得在等人。
  → 建議：每週加一個「已有 PM 經驗者：跳過 X 段，改做進階挑戰 Y」的標示區塊。
- **[P2-1] 上線後的維運缺席。** 全課從想法談到提案（W12），但 AI 產品真正的痛在上線之後：模型漂移、版本回溯、使用者行為變化導致效果衰退。W07 只談指標設計，沒談「指標開始變差時你要做什麼」。
  → 建議：不新增週次（會越界），在 W07 補一節 400 字的「效果衰退的三個徵兆與第一步」。
- **[P2-2] 案例取樣偏國際 B2C。** W01 三個案例（Duolingo／AI 寫作工具／Copilot）全是國際科技產品。大綱後段的金融、物流、法務案例平衡得多，但 W01 是第一印象。
  → 建議：依規範「至少一個企業內部流程場景」，把 W01 案例三替換或補一個台灣企業內部場景。

### 驗證者 2 · 具備專案管理經驗人士

**評分**：可執行性 4.0 / 時間估計合理性 **2.5** / 語彙對照 **1.5**

**問題**

- **[P0-1] 專案管理背景的人沒有語彙橋樑。** 課程通篇使用產品管理語言（PRD、persona、使用者故事、驗收條件、產品健康度），但這類學員熟悉的是 WBS、里程碑、風險登錄簿、變更控制。兩套語言講的是相近的事，課程卻沒給對照。
  → 建議：W01 新增一張「專案管理 vs 產品管理 vs AI 專案」三欄對照表（約 8 列），並在 W08 跨職能溝通再呼應一次。這是低成本、高回報的補丁。
- **[P0-2] 時數估計與實際落差過大。** 大綱寫「每週投入 3–5 小時」，但學習節奏表是 40 + 90 + 60 分鐘 + 作業 60–120 分鐘 = **4.2–5.5 小時**，且這是順利的情況。W06（完整 PRD + 可點擊原型）與 W12（七大件提案）保守估計各需 8–12 小時。
  → 建議：(a) 把每週節奏表的數字對齊大綱；(b) W06、W12 明確標示為「重週」並給出兩週的完成窗口；(c) 期末專案從 W09 開始分段交付，不要全押在 W12。
- **[P1-2] 交付物定義不夠可驗收。** W05「一份使用者痛點分析報告」、W07「一份指標儀表板規劃書」都沒說明長度、必備欄位、什麼叫做完。W01 的兩份作業在這點上做得好（有字數、有評分重點），應向全課看齊。
  → 建議：每個實作產出補上「必備欄位 + 篇幅 + 評分重點」三行。

### 驗證者 3 · 部門主管與團隊領導者

**評分**：決策價值 3.5 / 「給主管的提醒」品質 4.5 / 團隊層級產出 **2.0**

**做得好**

- W01 自學指南裡那則「用『做完沒』去追 AI 專案，會逼團隊給你假的確定性」的主管提醒，是全份教材最有價值的一段。**這個做法應該制度化成每週固定欄位**（已寫入規範第三節）。

**問題**

- **[P0-3] 前九週幾乎都是個人技能視角，主管的決策需求要等到 W10。** 一位主管最急的三個問題是：要不要投資？先做哪個？團隊用 AI 要訂什麼規矩？課程要到 W10 才碰第三個，前兩個散落在 W03 與 W11。
  → 建議：(a) W03 加一節「主管視角：審一個 AI 提案要問的四個問題」，直接沿用四問檢核表但換成審查者角度；(b) W10 的產出物明確定為「**團隊 AI 使用規範一頁紙**」——這是主管最想帶走的東西。
- **[P1-3] 對管理現實的假設偏理想。** W10「抗拒的真正來源不是不會用，是怕被取代」判斷正確，但沒處理更常見的情況：主管自己也沒把握、上面要求交 KPI、團隊沒有多餘人力做試點。
  → 建議：W10 補一個「資源不足下的最小可行導入」段落。

### 驗證者 4 · 數位轉型推動者

**評分**：落地路徑 3.0 / 傳統產業適用度 3.5 / 可衡量性 4.0

**問題**

- **[P0-4] 課程的起點與轉型推動者的真實起點不同。** 課程從「你有一個 AI 想法」開始（W03 評估一個想法），但推動者的起點是「我有一堆流程，該從哪一個下手」。缺少**流程盤點與優先排序**這一步，整條路徑就接不上。
  → 建議：W03 前段補「流程盤點：用影響 × 可行性矩陣挑出前三個切入點」，並讓 W03 的四問檢核表接在矩陣之後使用。W10 的路線圖再回頭引用同一份盤點。
- **[P1-4] 「非科技業套得上嗎」缺少明說。** 案例涵蓋醫療、物流、法務、金融，取樣其實不錯，但教材沒有明講「傳統產業的差異在哪」（資料多在紙本與舊系統、決策鏈長、風險承受度低）。
  → 建議：W03 或 W10 補一則 300 字的「傳統產業的三個額外限制」。
- **[P1-5] 缺少對上報告的材料。** 推動者學完需要的是一份能給高層看的東西。W11、W12 有提案，但中間八週沒有任何「可以直接對上報告」的產出。
  → 建議：把每階段結束的「一頁式反思」（已在評量中，佔 15%）改為「**一頁式對上簡報**」，一石二鳥。

### 驗證者 5 · 非產品經理背景的職場人 ★ 關鍵驗證者

**評分**：可理解性 **3.0** / 名詞友善度 **2.0** / 作業可獨力完成 3.5

**這是分數最低的一類，也是最該優先處理的。**

**問題**

- **[P0-5] 大量 PM 術語未定義就使用。** 盤點如下：
  | 名詞 | 出現位置 | 是否有定義 |
  |---|---|---|
  | PRD | W06、W01 能力地圖 | ✗ |
  | 使用者故事、驗收條件 | W06 | ✗ |
  | persona（人物誌） | W05 | 僅中文帶過 |
  | 使用者旅程 | W05 | ✗ |
  | A/B 測試、離線／線上指標 | W07 | ✗ |
  | 優先級排序、需求定義 | W01 開場即用 | ✗ |
  | RAG、微調、context window | W02 | 說「講產品意義」，未定義 |
  | 單位經濟學、成效制定價 | W11 | ✗ |
  → 建議：(a) 每週新增「本週新名詞」欄位（≤8 個，各一句白話）；(b) 全課附一份 `00-課程大綱/名詞對照表.md`，中英對照 + 一句話解釋 + 首次出現週次。
- **[P1-6] W01 作業 2 的能力地圖，要求學員自評八項「還沒學過的能力」。** 對零基礎者這會造成挫折感（八項全填 1 分）。設計意圖是對照 W12 進步，方向對，但需要一句話拆掉壓力。
  → 建議：作業說明加上「**現在多數項目落在 1–2 分是正常的，這份表的用途是 12 週後的對照組，不是評價你現在的能力。**」
- **[P1-7] 自我檢驗六題全為申論。** 對非 PM 背景者門檻偏高，容易直接跳過。
  → 建議：依規範將前兩題改為判斷／選擇題當暖身，後四題維持申論。
- **[P2-3] 作業缺少替代版本。** W05（要有訪談逐字稿）、W06（要有一個產品需求）、W03（要有公司內部的 AI 想法）都預設學員手上有真實素材。沒有的人會卡住。
  → 建議：每份作業附「**沒有真實素材時的替代題**」，並提供一份共用的情境素材包。

## 三、跨角色共通發現

- **[P2-4] 缺少「課前準備：工具取得」的入口文件。** 廠牌中立是對的邊界，但副作用是新手不知道第一步該開哪個工具。
  → 建議：新增 `00-課程大綱/課前準備-工具與帳號.md`，寫**選擇準則**（能對話、能讀檔、公司允許）而非指定品牌，並提醒公司資料的使用規定。符合邊界 B，不會過期。
- **[P2-5] 案例沒有查證日期標註。** 大綱已寫「超過 12 個月的案例要重新查證」，但教材中沒有可據以查核的日期欄位。
  → 建議：每個案例卡片加一行「查證日期：YYYY-MM」。

## 五、對 W02–W12 開發的預先提醒

| 週次 | 最容易越界的地方 | 守線方式 |
|---|---|---|
| W02 | 講 LLM 原理時滑進技術細節 | 每個名詞只回答「它在會議上代表什麼決策」 |
| W03 | 可行性檢核表變成資料科學評估表 | 四問維持白話，不引入統計門檻計算 |

## 六、待真人驗證者複核

本報告為依規範進行的模擬審查，以下三項**必須由真人驗證者確認**，模擬無法取代：

1. **實際耗時**——請至少 2 位驗證者實測 W01（閱讀 + 作業）並回報分鐘數。
2. **看不懂的段落行號**——請 1 位非 PM 背景者逐段標註，這是名詞表的取材來源。
3. **案例的事實正確性與時效**——請現職 PM 複核 W01 三則案例的細節與結論。

複核結果請依規範第五節格式，存為 `WNN-驗證回饋-<角色>.md`。
